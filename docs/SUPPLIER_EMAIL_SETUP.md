# Public supplier invitations

## Deploy on Render

1. Push this source tree to a GitHub repository connected to your Render account. Exclude `.env.local`, `data/`, `.next/` and `node_modules/` (the included `.gitignore` excludes them). No Git remote is configured in the current checkout yet.
2. In Render choose **New → Blueprint**, connect that repository and select the included `render.yaml`.
3. Review the Starter service and persistent disk cost before creating it. This SQLite architecture uses one instance and needs persistent storage; an ephemeral free filesystem will lose records.
4. Enter the environment values requested by the Blueprint. Use a fresh production `SESSION_SECRET` and `AUTH_SECRET` (generated by the Blueprint), your owner OAuth configuration, and the existing PayPal sandbox credentials. Add Resend sender credentials below.
5. After Render assigns the service URL, set `APP_URL` and, if you use it, `AUTH_URL` to that HTTPS origin. Update GitHub's OAuth callback to that origin plus `/api/auth/callback/github`. Redeploy.
6. Add optional providers in Render Environment separately: Google Places, Sarvam (all `SARVAM_*` values from `.env.example`), and Elastic when implemented. Local `.env.local` is not uploaded automatically. Keep `LOCAL_AI_ENABLED` disabled on a public instance; use owner sign-in.
7. Verify `/api/health` returns `{"status":"ok"}`. Sign into the deployed app, open Settings and resolve the hosting/email requirements. Create a request on the deployed instance and generate a fresh supplier link.
8. Send one invitation to a consenting supplier and open it on a different device. Submit the quotation there, then verify it appears in the buyer's deployed workspace. Check Resend's delivery status independently.

Startup runs database migrations on the mounted disk before starting the web app and worker. Provider credentials remain server-side. Both the web app and worker share the disk within this single service.

Deploy the same application and database to a public HTTPS host. The included `render.yaml` configures one Render service with a persistent disk for SQLite and uploaded files. A new hosted instance does not automatically contain your local requests: create the request there or migrate a consistent SQLite backup and private assets before inviting suppliers. Do not copy an active SQLite file without its WAL state.

Set `APP_URL=https://your-service.onrender.com` (or your custom domain) on that instance. Use the same public origin in GitHub OAuth configuration, with callback `/api/auth/callback/github`, and register the deployed `/api/webhooks/paypal` endpoint with PayPal. Keep PayPal sandbox accounts for the hackathon. Restart after environment changes. Setting a public URL alone does not deploy the app or make the local database public.

## Email delivery

1. Create a Resend account and verify a sending domain you control using its DNS instructions. Test-domain restrictions may prevent sending to arbitrary suppliers.
2. Create a sending API key. Set `RESEND_API_KEY` privately on the server.
3. Set `EMAIL_FROM=ProcureProof <quotes@your-verified-domain.com>`.
4. Add the supplier's correct email in Suppliers. In the connected owner workspace, confirm a request and create an invitation.
5. Review the displayed public URL and recipient, then click **Email invitation**. No email is sent just by creating a link.

The supplier opens the private URL on their own device without buyer sign-in, submits a written quote, and can return to accept an agreement or upload evidence. Links expire after seven days. The email contains the request title and scoped portal link, without the buyer's budget or competing offers.

“Email accepted” means Resend accepted it, not that it reached the inbox. Check Resend for delivery/bounce status. Sending/uncertain attempts block repeated submission for that invitation to avoid duplicate mail. Check the provider before creating a replacement invitation. No inbox delivery webhook is implemented.

Official reference: https://resend.com/docs/api-reference/emails/send-email
